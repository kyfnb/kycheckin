# 가맹점 방문 확인 시스템 (QR + GPS 이중검증 · 이메일 승인제 · 매장정보 실시간 연동)

앱시트 없이 만든 커스텀 웹앱(PWA)입니다. SV(슈퍼바이저)가 이름/회사이메일로 접속을 요청하고,
관리자가 승인하면 가맹점 QR을 스캔해서 GPS 위치까지 함께 확인한 방문 이력을
**구글 스프레드시트**에 기록합니다.

가맹점 정보(브랜드, 매장명, 위경도, 운영상태)는 이 앱이 따로 관리하지 않고,
**회사에서 이미 쓰고 있는 "매장정보" 스프레드시트를 실시간으로 그대로 조회**합니다.

앱스토어 등록 없이, 웹 링크만으로 사용하고 "홈 화면에 추가"하면 앱처럼 아이콘이 생깁니다.

---

## 0. 전체 그림 먼저 이해하기

```
[SV: 이름/이메일 입력] → [관리자 승인 확인] → [QR 스캔] → [매장정보에서 실시간 조회]
     → [휴대폰 GPS 확인] → [거리+QR유효시간 검증] → [방문기록 저장]
           ↑                          ↓                        ↓
     Google Apps Script  ───→  매장정보 시트(외부, 읽기전용)   Visits 시트(이 앱 소유)
```

- **매장정보 시트** (별도 파일, 읽기 전용): 브랜드, 매장명, 운영상황, 위경도, 고유코드(아름넷)가
  담겨 있는 회사의 매장 마스터 데이터입니다. 이 앱은 여기서 **조회만** 하고, 절대 수정하지 않습니다.
  `폐점`, `양도완료` 상태인 매장은 자동으로 제외됩니다.
- **로그인**: 이름과 회사 이메일을 입력하면 됩니다 (비밀번호 없음). 처음 입력하는
  사람은 자동으로 "승인 대기" 상태가 되고, 관리자가 시트에서 승인해야 사용할 수 있습니다.
- **권한 등급 (Staff 시트의 role/브랜드/팀 열)**: 승인만으로는 부족하고, 역할과 (리더·Head는)
  담당 범위도 함께 지정해야 합니다.
  - **담당자(staff)** — 기본값. 매장정보 시트에서 본인이 담당자(F열)로 등록된 매장만
    검색/조회할 수 있고, 방문 이력도 본인 것만 볼 수 있습니다.
  - **리더(leader)** — Staff 시트의 **브랜드**, **팀** 칸에 지정된 소속만 검색/조회할 수
    있습니다. 다른 팀은 필터로도 볼 수 없습니다(서버가 강제로 범위를 제한합니다). **브랜드도
    팀도 여러 개면 쉼표로 구분해서 입력**하세요 (예: 브랜드=`두찜,떡참`, 팀=`오픈팀` → 두 브랜드의
    "오픈팀"을 모두 봄. 또는 브랜드=`두찜`, 팀=`1T,2T` → 두찜의 1T·2T 두 팀을 봄). 브랜드/팀은
    매장정보 시트의 표기와 정확히 똑같이 입력해야 합니다.
  - **Head** — Staff 시트의 **브랜드** 칸에 지정된 브랜드(들)를 조회할 수 있습니다. 여러
    브랜드면 쉼표로 구분해서 입력하세요 (예: `두찜,숯불`). **팀 칸을 비워두면** 그 브랜드(들)의
    **전체 팀**을 보고, **팀 칸에 값을 넣으면**(리더처럼 쉼표로 여러 개 가능) 그 팀들로만
    범위가 좁혀집니다. 리더처럼 브랜드/팀/담당자 필터를 쓸 수 있지만, 본인이 지정된 범위
    밖으로는 못 나갑니다. 관리자와 달리 방문 이력 수정/삭제 권한은 없습니다.
  - **관리자(admin)** — 전체 매장/전체 이력을 자유롭게 필터링해서 볼 수 있고, 방문 이력의
    확인여부 수정, 삭제 권한까지 있습니다.
  새로 가입 요청한 사람은 자동으로 `staff`가 되고, 관리자가 `Staff` 시트에서 `role`(과
  필요시 브랜드/팀) 칸을 직접 바꿔주면 됩니다.
- **로그인 비밀번호**: 이름/이메일 아이디와 함께 **본인이 정한 비밀번호**를 입력해야 접속돼요.
  - 처음 접속할 때 입력한 비밀번호가 그 사람의 비밀번호로 저장됩니다 (평문이 아니라
    **SHA-256 해시**로 저장되어, 시트를 열어봐도 실제 비밀번호는 안 보여요).
  - **비밀번호를 잊어버렸거나 초기화하고 싶으면**, 관리자가 `Staff` 시트에서 그 사람의
    `비밀번호(해시)` 칸 내용을 **지우기만 하면** 됩니다 — 다음 로그인 때 입력하는 비밀번호가
    새 비밀번호로 자동 설정돼요.
  - 이미 승인되어 있던 기존 계정들은 비밀번호 칸이 비어있는데, **다음 로그인 때 처음
    입력하는 비밀번호가 그대로 등록**되니 별도 초기화 작업이 필요 없습니다.
  - ⚠️ 이건 별도 서버 없는 구조(구글시트+정적 웹페이지)의 한계상, 은행 수준의 보안은
    아니에요 — "관계없는 사람이 우연히 못 들어오게 막는" 1차 방어선 정도로 생각해주세요.
- **신규 요청 자동 알림**: 누군가 처음 "접속 요청하기"를 누르면, `role`이 `admin`이고
  `status`가 `approved`인 모든 계정에게 자동으로 이메일이 갑니다 (구글시트 바로가기 링크 포함).
  아직 admin으로 지정된 사람이 한 명도 없으면 알림이 조용히 생략됩니다.
- **Staff 시트** (이 앱 소유): 요청한 사람 목록, 승인 상태(pending/approved/rejected), 역할(role),
  리더/Head의 담당 브랜드·팀, 비밀번호(해시).
  `status`를 시트에서 직접 `approved`로 바꾸면, `approvedAt` 칸에 그 시각이 **자동으로** 채워집니다
  (`Code.gs`의 `onEdit` 함수가 처리해요 — 별도 실행 없이 시트에 코드만 있으면 바로 작동합니다).
- **Visits 시트** (이 앱 소유): 방문 기록(누가, 언제, 어느 가맹점, 거리, 확인여부)
- **회전 QR**: 매장 POS 화면에 띄워두는 QR코드가 1분마다 자동으로 바뀝니다. 스캔 시
  서버가 "지금 시점에 가까운 QR인지"를 검증해서, 사진으로 캡처해둔 QR 재사용을 막습니다.

## 1. 스프레드시트 + Apps Script 설정

1. https://sheets.google.com 에서 새 스프레드시트 생성 (이름 예: `가맹점 방문 관리`)
   - ⚠️ 이 시트는 **매장정보 시트와는 다른, 이 앱 전용의 새 시트**입니다. 헷갈리지 마세요.
2. 상단 메뉴 **확장 프로그램 → Apps Script** 클릭 → 새 편집기 창이 열립니다.
3. 기본으로 있는 코드를 전부 지우고, 이 프로젝트의 **`Code.gs` 파일 내용을 그대로 복사해서
   붙여넣기** 하세요.
4. 편집기 상단 저장(💾) 클릭 → 프로젝트 이름 아무거나 입력
5. 함수 선택 드롭다운에서 **`setupSheets`** 선택 → ▶ 실행 버튼 클릭
   - 처음 실행 시 "권한 승인 필요" 팝업이 뜹니다. 이번엔 **매장정보 시트에 접근할 권한도
     함께 요청**됩니다 (다른 스프레드시트를 읽어와야 하므로) → 본인 구글 계정 선택 →
     "고급" → "(프로젝트명)(안전하지 않음)으로 이동" → 허용
   - 실행이 끝나면 스프레드시트로 돌아가서 `Visits`, `Staff` 탭이 생겼는지 확인하세요.
     (기본 `시트1`은 안 쓰면 삭제해도 됩니다)
6. **중요**: Apps Script를 실행하는 구글 계정이 매장정보 시트를 **최소 "뷰어" 권한으로라도
   열어볼 수 있어야** 합니다. 매장정보 시트 소유자에게 공유 권한을 요청하세요.

### 웹앱으로 배포하기

1. Apps Script 편집기 우측 상단 **배포 → 새 배포**
2. 톱니바퀴(⚙) 아이콘 → **유형 선택: 웹 앱**
3. 설정:
   - 설명: 아무거나 (예: `franchise-visit-api`)
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포** 클릭 → 권한 승인 → 완료되면 **웹 앱 URL**이 나옵니다.
5. 이 URL을 복사해서 `js/sheets-config.js`의 `API_URL` 값에 붙여넣으세요.

> ⚠️ **코드를 수정할 때마다** Apps Script는 자동 반영되지 않습니다. 편집기에서
> **배포 → 배포 관리 → 수정(연필 아이콘) → 새 버전 → 배포**를 눌러야 변경사항이 적용됩니다.

### 매장정보 시트 연결 정보가 바뀐다면

`Code.gs` 상단에 아래 값들이 있습니다. 매장정보 시트의 구조(열 순서, 탭)가 바뀌면 여기를 수정하세요.

```javascript
const MASTER_SHEET_ID = '16Dzw_zlINqUMNBHR1quNo73RgmsNlEHoQm-wkrPvQhE';
// 브랜드별로 탭이 나뉘어 있어서, 모든 탭 이름을 나열합니다.
const MASTER_SHEET_NAMES = ['두찜', '떡참', '숯불'];
const MASTER_DATA_START_ROW = 4;     // 실제 데이터가 시작하는 행 번호

const MASTER_COL = {
  brand: 1,   // B열: 브랜드
  name: 2,    // C열: 매장명
  status: 3,  // D열: 운영상황
  manager: 5, // F열: 담당자 이름 (미방문 매장 조회에 사용)
  code: 8,    // I열: 아름넷 코드 (고유식별값)
  lat: 17,    // R열: 위도
  lng: 18     // S열: 경도
};

const EXCLUDED_STATUSES = ['폐점', '양도완료']; // 이 상태인 매장은 QR/방문등록 대상에서 제외
```

> ⚠️ **"미방문 매장" 기능은 이름을 문자 그대로 비교합니다.** 로그인할 때 입력한 이름과
> 매장정보 시트 F열(담당자)의 이름이 정확히 같아야(띄어쓰기 포함) 매칭됩니다. 동명이인이
> 있거나 표기가 다르면(예: "김수퍼" vs "김 수퍼") 매칭이 안 될 수 있어요.

새 브랜드 탭이 추가되면 `MASTER_SHEET_NAMES` 배열에 탭 이름만 추가하면 됩니다.

### 시트 열 제목을 한글로 바꾸기 (기존 사용자만)

**`renameHeadersToKorean`** 함수를 한 번 실행해주세요. `Visits`, `Staff` 시트의 영문 열 제목이
(예: `checkInAt` → `입장일시`, `svName` → `담당자이름`) 전부 한글로 바뀝니다. **데이터나 코드
동작에는 전혀 영향이 없어요** — 코드는 열 이름이 아니라 열 순서(번호)로 데이터를 읽고 쓰기
때문에, 제목만 안전하게 바뀝니다. 여러 번 실행해도 문제없어요.

새로 `setupSheets`를 실행해서 만드는 시트는 처음부터 한글 제목으로 생성됩니다.

### 방문 기록에 QR 유효여부 열 추가하기 (기존 사용자만)

**`addQrValidColumnsIfMissing`** 함수를 한 번 실행해주세요. `Visits` 시트에 `checkInQrValid`,
`checkOutQrValid` 열이 추가됩니다. 이 두 열 덕분에 "⚠ 확인필요"로 표시된 기록이
**거리 때문인지, QR이 만료돼서인지**를 구분할 수 있어요. 기존 기록들은 이 값을 알 수 없어서
빈칸으로 남고, 이 함수를 실행한 이후의 새 기록부터 자동으로 채워집니다.

### 리더/Head 권한 + 브랜드·팀별 조회 탭을 쓰려면 (기존 사용자만)

순서대로 실행해주세요 (한 번씩만 실행하면 됩니다):

1. **`addBrandTeamColumnsToStaffIfMissing`** — Staff 시트에 브랜드/팀 열 추가
2. **`addBrandTeamColumnsToVisitsIfMissing`** — Visits 시트에 브랜드/팀 열 추가
3. **`fillBrandTeamForExistingVisits`** — (선택) 기존 방문 기록에도 브랜드/팀을 소급 적용
4. **`createBrandTeamViewSheets`** — 브랜드별·팀별 조회 탭을 자동 생성

이후 매장정보에 새 브랜드나 팀이 추가되면, **`createBrandTeamViewSheets`**를 다시 실행하면
새 탭이 자동으로 생깁니다. 이 탭들은 `Visits` 시트를 실시간으로 필터링해서 보여주는
**조회 전용**(QUERY 수식) 탭이라, 직접 입력/수정하면 안 됩니다 — 항상 `Visits` 시트에서만
데이터를 다루고, 이 탭들은 보기용으로만 활용해주세요.

리더/Head로 지정할 사람은 `Staff` 시트에서 `role`을 `leader` 또는 `head`로 바꾼 뒤,
**브랜드**/**팀** 칸도 함께 채워주셔야 실제로 범위 제한이 적용됩니다 (자세한 입력 방법은
위의 "권한 등급" 설명을 참고해주세요).

### 속도 개선: 매장정보 캐시

매장정보는 다른 스프레드시트라서, 매번 새로 열어서 전체를 읽으면 느립니다. 그래서 한 번 읽은
내용을 **5분간(`MASTER_CACHE_SECONDS`) 캐시**해두고, 그 안에서는 브랜드/팀/담당자 필터나 매장
검색이 캐시된 데이터로 빠르게 처리됩니다. 매장정보를 방금 수정했는데 앱에 바로 반영이 안 되면,
Apps Script 편집기에서 **`clearMasterDataCache`** 함수를 한 번 실행하면 즉시 새로 읽어옵니다
(5분 기다려도 자동으로 갱신되니, 급할 때만 실행하면 됩니다).

### 이미 사용 중이던 Visits 시트에 사진 열 추가하기 (기존 사용자만)

이미 `Visits` 시트를 쓰고 계셨다면, `Code.gs`를 새로 붙여넣은 후 **`addPhotoUrlColumnIfMissing`**
함수를 한 번 실행해주세요 (함수 선택 드롭다운에서 골라 ▶ 실행). `photoUrl` 열이 자동으로 추가됩니다.
새로 `setupSheets`를 실행하는 경우엔 이미 포함되어 있어서 필요 없습니다.

### 입장/퇴장 기능 도입 전부터 쓰던 Visits 시트라면 (기존 사용자만)

**`migrateToCheckInOutColumns`** 함수를 한 번 실행해주세요. 기존 열 이름이 자동으로
`checkInAt`, `checkInDistance` 등으로 바뀌고(데이터는 그대로 유지됩니다 — 전부 "입장" 기록으로
간주됩니다), 퇴장 관련 열들이 새로 추가됩니다. 이미 마이그레이션되어 있으면 아무 일도 일어나지 않아요.

### 방문 기록 수정/삭제 기능을 쓰려면 (기존 사용자만)

**`addVisitIdColumnIfMissing`** 함수를 한 번 실행해주세요. `Visits` 시트에 각 방문 기록을
고유하게 식별하는 `visitId` 열이 추가되고, 기존 행에도 자동으로 ID가 채워집니다.

### 권한(담당자/리더/관리자) 기능을 쓰려면 (기존 사용자만) + 최초 관리자 지정

**`addRoleColumnIfMissing`** 함수를 한 번 실행해주세요. `Staff` 시트에 `role` 열이 추가되고,
기존 승인자는 전부 기본값 `staff`(담당자)로 채워집니다.

실행 후, **본인(관리자가 되실 분)의 행을 `Staff` 시트에서 찾아 `role` 칸을 직접 `admin`으로
바꿔주세요.** 리더로 지정할 사람이 있다면 `leader`로 바꿔주시면 됩니다. (이 작업은 앱이 아니라
구글시트를 직접 열어서 수동으로 하는 거예요 — 앱 안에는 role을 바꾸는 화면이 없습니다.)

## 4. 사용 순서

0. **최초 접속 승인**: SV가 처음 접속해서 이름/이메일을 입력하면 "승인 대기" 화면이 뜹니다.
   관리자가 `Staff` 시트에서 해당 이메일의 `status`를 `approved`로 바꿔줘야 다음
   접속부터 통과됩니다. **이때 `role` 칸도 확인해서** 필요하면 `leader`/`admin`으로 바꿔주세요
   (안 바꾸면 기본값 `staff`로 남아요).
1. **매장 QR 화면 준비**: 담당자가 앱에 로그인 → "QRCODE 설치" → 브랜드/매장명/코드로
   검색 → 원하는 매장 선택 → 나온 링크를 매장 POS 브라우저에서 열고 그 화면을 그대로 켜두세요.
   (가맹점을 새로 등록하는 게 아니라, 매장정보 시트에 이미 있는 데이터를 찾는 것입니다.)
   - **담당자(staff)**는 본인이 담당자로 등록된 매장만 검색됩니다 (필터 UI 자체가 안 보여요).
   - **리더/관리자**는 전체 매장을 검색할 수 있고, 브랜드/팀/담당자 필터도 쓸 수 있어요.
2. **방문 등록 (입장/퇴장 자동 판별)**: SV가 앱에 로그인 → "QR SCAN" → 매장 화면에 떠 있는
   QR을 스캔 → 자동으로 GPS 위치 확인.
   - **입장**(그 매장에 열려있는 입장 기록이 없을 때): 추가로 **매장 내부(POS 화면 등) 사진 촬영**이
     필수입니다. 촬영 후 "입장 등록 완료"를 눌러야 저장돼요.
   - **퇴장**(이미 입장 기록이 있을 때): 사진 없이 **QR + GPS만으로 바로 자동 저장**되고,
     입장~퇴장 사이 체류시간(분)이 함께 계산됩니다.
   - 단, 입장한 지 **16시간이 넘도록 퇴장을 안 찍은 기록**은 "놓친 입장"으로 간주되어 무시됩니다 —
     그 상태로 다시 그 매장을 방문해서 스캔하면, 오래된 기록과 잘못 짝지어지지 않고 **새 입장**으로 처리돼요.
     (놓친 입장 건은 방문 이력에 "⚠ 퇴장 누락"으로 표시되고, 체류시간은 계산되지 않습니다.)
   - 거리가 100m 이내이고 QR이 1분 이내에 발급된 것이면 "확인됨", 아니면 "위치 불일치" 또는 "QR 만료됨"
   (구글시트의 `Visits` 탭에서 입장 시 새 줄이 추가되고, 퇴장 시 같은 줄의 퇴장 관련 칸이 채워집니다.
   사진 파일 자체는 구글드라이브의 "가맹점방문사진" 폴더에 저장됩니다.)
3. **"점검중" 배너**: 입장을 찍으면, 앱의 어느 화면에 있든 상단에 "OO매장 점검중 · 경과시간"
   배너가 계속 떠 있습니다. 탭하면 바로 스캔 화면(퇴장 찍는 화면)으로 이동해요. 퇴장을 찍으면
   배너가 사라집니다. (진짜 시스템 전체 오버레이는 웹앱에서 만들 수 없어서, 앱 안에서
   항상 보이는 배너로 구현했습니다.)
3-1. **자동 주기적 위치 기록**: 입장한 뒤 앱이 켜져있는 동안, **5분마다 자동으로 현재 위치를
   기록**해서 `LocationPings` 시트에 저장합니다. 방문 이력에서 각 기록의 "이동경로" 링크를
   누르면, 그 방문 중에 기록된 위치들을 이어서 구글지도 경로로 한 번에 볼 수 있어요.
   ⚠️ **웹앱의 한계**: 화면을 끄거나 다른 앱으로 전환하면 브라우저가 자바스크립트 실행을
   멈추기 때문에 기록이 중단됩니다. 앱을 계속 켜두고 있을 때만 작동하는, "완벽한 백그라운드
   추적"이 아닌 "보조적인 이동 확인 도구"로 봐주세요.
4. **방문 이력**: "방문 이력" 메뉴에서 세 가지 방식으로 확인할 수 있어요.
   - **목록**: 최근 1개월 / 3개월 / 직접입력(시작일~종료일) 중 기간을 골라서 조회.
     **담당자**는 "내 방문만" 보이고, **리더/관리자**는 "전체 보기"도 가능합니다.
   - **팀/담당자 필터 (리더·관리자 전용)**: 목록/캘린더/미방문 매장 화면 상단에
     **브랜드 → 팀 → 담당자** 순서로 연동되는 드롭다운이 나타납니다. 브랜드를 고르면
     그 브랜드에 속한 팀만, 팀을 고르면 그 팀 소속 담당자만 다음 드롭다운에 나타나요.
     팀 이름은 매장정보 원본 값(예: "두찜1T")에서 숫자만 뽑아 "1팀"처럼 보기 좋게 표시됩니다.
     이 필터는 목록·캘린더·미방문 매장 화면 모두에 동일하게 적용됩니다.
   - **캘린더**: 월별 달력에서 방문한 날짜에 점이 표시되고, 날짜를 탭하면 그날 방문한 매장 목록이 나와요
   - **미방문 매장**: 로그인한 이름이 매장정보 시트의 **담당자(F열)**와 일치하는 매장 중,
     최근 60일간 한 번도 방문하지 않은 매장을 보여줘요
5. **관리자 기능**: `role`이 `admin`인 계정으로 로그인하면, 방문 이력 목록의 각 항목 아래에
   **"입장확인 처리/취소"**, **"퇴장확인 처리/취소"**, **"삭제"** 버튼이 나타납니다. 실수로 잘못
   기록된 방문을 바로잡거나, 완전히 지울 수 있어요. (서버가 요청자의 실제 role을 다시 확인하므로,
   admin이 아닌 사람이 임의로 이 기능을 쓸 수는 없습니다.)

## 6. 자주 조정하는 값

- **방문 허용 반경**: `js/utils.js`의 `VISIT_RADIUS_METERS` (기본 100m)
- **QR 유효 시간**: `js/store-display.js`와 `Code.gs` 양쪽의 `WINDOW_SECONDS` /
  `QR_WINDOW_SECONDS` (기본 1분, 60초). **두 값은 반드시 동일해야 합니다.**
- **놓친 입장 처리 기준**: `Code.gs`의 `MAX_OPEN_SESSION_HOURS` (기본 16시간). 이 시간이
  지나도록 퇴장을 안 찍으면 그 입장 기록은 무시되고, 다음 방문은 새 입장으로 처리됩니다.
  (`js/history.js`에도 같은 기준(16)으로 "퇴장 누락" 표시 로직이 있어서, 값을 바꾸면 두 곳 다 맞춰주세요.)
- **QR/방문등록 제외 상태**: `Code.gs`의 `EXCLUDED_STATUSES` (기본: 폐점, 양도완료)
- **미방문 매장 기준일수**: `Code.gs`의 `UNVISITED_THRESHOLD_DAYS` (기본 60일)
- **자동 위치기록 주기**: `js/utils.js`의 `LOCATION_PING_INTERVAL_MS` (기본 5분).
  간격을 줄이면 더 촘촘하게 기록되지만, 배터리·데이터 사용량과 시트 용량이 더 늘어나요.
- **GPS 오차(정확도) 허용 기준**: `Code.gs`의 `MAX_GPS_ACCURACY_METERS` (기본 200m). 이 값을
  넘으면 거리가 반경 이내로 계산돼도 "신뢰할 수 없는 위치"로 보고 확인 실패 처리됩니다.
  (`js/history.js`에도 같은 기준(200)으로 사유 표시 로직이 있어서, 값을 바꾸면 두 곳 다 맞춰주세요.)
- **디자인 색상**: `css/style.css` 상단 `:root` 변수들

## 7. 다음 단계로 고려할 만한 개선

- **승인 알림 자동화**: 관리자가 직접 `Staff` 시트를 열어 상태를 바꾸는 대신,
  `requestAccess_` 함수에서 `MailApp.sendEmail(...)`로 자동 알림 메일을 보낼 수 있어요.
- **간단한 확인코드 추가**: 이메일 인증이 걱정되면, 승인 시 4자리 코드를 발급해서
  최초 접속 때 코드를 함께 입력하게 하는 방식으로 신뢰도를 높일 수 있습니다.
- **이상 위치/QR 만료 알림**: `logVisit_` 함수에서 `verified === false`이거나
  `qrValid === false`일 때 관리자에게 이메일을 보내는 코드를 추가하면 실시간 알림도 가능합니다.
- **매장정보 캐싱**: 매장 수가 아주 많아지면 매번 매장정보 전체를 훑는 대신,
  `CacheService`로 일정 시간 캐싱해서 조회 속도를 높일 수 있어요.
